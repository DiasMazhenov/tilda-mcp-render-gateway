# Tilda MCP gateway · именованные подключения

Один универсальный MCP для веб-чата ChatGPT. Именованные ключи хранятся в Neon в зашифрованном виде. Управлять ими можно на защищённой странице сервера. В каждом запросе явно выбирается подключение; параллельные чаты не переключают общий активный проект.

- MCP: `https://tilda-mcp-render-gateway.onrender.com/mcp/tilda`
- Управление: `https://tilda-mcp-render-gateway.onrender.com/settings`

Работает независимо от Codex и компьютера владельца. Это персональный шлюз одного владельца, не многопользовательский сервис.

## Проверенный статус на 6 ноября 2026

Версия шлюза: **0.4.1**. Подключение в веб-версии ChatGPT прошло полный путь ChatGPT → Render → Neon → Tilda. Через сохранённое подключение Comfortclinic.kz успешно получен список из 23 страниц. Это пример проверки: шлюз остаётся универсальным для других ключей и проектов.

- Публичный `/healthz` вернул HTTP 200 и `{"ok":true,"service":"tilda-mcp-gateway"}`.
- Работают OAuth discovery, страница управления и постоянное хранилище Neon.
- При последней проверке прошли 16 локальных тестов и два браузерных сценария Chromium с разными callback URL ChatGPT.
- Внешний планировщик пробуждения настраивается отдельно по инструкции ниже. Само наличие этой инструкции не означает, что задание уже создано.

## 1. Neon

Создай отдельный проект Neon на Free: https://console.neon.tech/.
В проекте нажми Connect, выбери базу и роль и скопируй PostgreSQL connection string.
Вставь **только в Render Environment** под именем DATABASE_URL. Не отправляй строку в чат и не сохраняй в GitHub: она содержит пароль базы.

Приложение при первом запуске создаёт только свою схему `tilda_gateway` и таблицу `connections`. Имена и значения передаются параметрами. Схема и таблица закрыты для PUBLIC. Используй отдельную базу для шлюза; не включай публичный Data API для этой схемы.

## 2. Render

New → Web Service → репозиторий DiasMazhenov/tilda-mcp-render-gateway → ветка main.

| Настройка | Значение |
| --- | --- |
| Runtime | Node |
| Build | `npm ci --omit=dev` |
| Start | `npm start` |
| Health Check | `/healthz` |
| Plan | Free для начала |

Environment:

| Переменная | Значение |
| --- | --- |
| NODE_VERSION | `24` |
| PUBLIC_BASE_URL | `https://tilda-mcp-render-gateway.onrender.com`, без пути и завершающего слеша |
| OAUTH_SIGNING_SECRET | 64 случайных hex-символа, например результат `openssl rand -hex 32` |
| ADMIN_PASSWORD | Уникальный пароль от 10 символов |
| DATABASE_URL | Строка подключения Neon из Connect |

Все ключи Tilda вводятся через интерфейс. Переменных TILDA_TOKEN_* нет.

Не меняй OAUTH_SIGNING_SECRET после сохранения ключей: от него производится ключ шифрования базы. Если его потерять, сохранённые ключи Tilda нельзя будет расшифровать. Для переноса сохрани зашифрованную базу и этот секрет отдельно в менеджере паролей. Пароль владельца можно менять; это завершает старые сессии страницы настроек, но не отзывает уже выданные OAuth-доступы ChatGPT.

После сохранения настроек дождись Live. `/healthz` проверяет работу процесса, а не действительность ключей Tilda.

## 3. Добавление нескольких ключей

1. Открой `/settings`.
2. Войди с ADMIN_PASSWORD.
3. Введи название проекта и токен Tilda MCP. Префикс Bearer необязателен.
4. Добавь остальные проекты.

Ключи после сохранения не выводятся ни в HTML, ни в список MCP-подключений. Можно менять названия, заменять токены и удалять записи. Пустое поле нового токена при редактировании сохраняет прежний. Одинаковые названия без учёта регистра не допускаются. Удаление требует отдельной галочки.

После удаления подключения новые вызовы по его ID прекращаются. Уже выполняющийся запрос не отменяется.
Название подключения не ограничивает исходный токен одним проектом Tilda: реальные права определяет Tilda.

## 4. Подключение веб-чата

В веб-версии ChatGPT открой меню добавления приложений/плагинов → **Добавить пользовательский сервер MCP**. Если пункт скрыт, проверь доступность и включение режима разработчика в настройках своего аккаунта. Заполни форму:

| Поле | Значение |
| --- | --- |
| Название | Tilda MCP |
| Server URL | `https://tilda-mcp-render-gateway.onrender.com/mcp/tilda` |
| Authentication | OAuth |
| Client registration | DCR |
| Client ID / Secret | Не заполняются вручную |
| Token endpoint auth method | none |

Предупреждение «CIMD недоступен, поскольку сервер не сообщил о поддержке CIMD» нормально: здесь используется **DCR**. При авторизации введи пароль владельца. Новый именованный ключ можно добавить в этой форме или позже на странице /settings. При настроенной базе поля нового ключа необязательны: достаточно уже сохранённых подключений.

Стандартные настройки ChatGPT не расширяются произвольными полями. Управление ключами находится на защищённой странице шлюза; ссылку также возвращает list_connections.

Для этого подключения не нужен архив старого плагина с прямым Bearer-доступом и ссылка, открывающая Codex. В веб-чате используется пользовательский MCP-сервер Render.

### В переписке

Введи `@`, выбери подключённое приложение **Tilda MCP** и отправь запрос. Названия сохранённых подключений можно указывать прямо в сообщениях.

Примеры:

- Покажи сохранённые подключения Tilda.
- Покажи доступные инструменты проекта «Название проекта».
- Для проекта «Название проекта» покажи страницы.

Инструменты шлюза:
- `list_connections`: названия и ID без секретов, ссылка управления.
- `list_tilda_tools(connection_id)`: реальные имена, описания и схемы инструментов Tilda для выбранного ключа.
- `call_tilda_tool(connection_id, tool_name, arguments)`: вызов выбранного инструмента.

Активного проекта на весь сервер нет. Каждый вызов обязан содержать connection_id. Если название не указано или непонятно, агент должен уточнить выбор. Переименование сохраняет ID. Замена токена действует для следующих вызовов без переподключения плагина.

Обёртка call_tilda_tool помечена как потенциально изменяющая данные, поскольку через неё доступны и чтение, и запись. Подтверждения зависят от настроек ChatGPT. Секреты нельзя добавлять через чат: только через защищённую форму.

## Автоматическое пробуждение Render

Render Free засыпает после 15 минут без входящих запросов. Для регулярного обращения можно использовать внешний сервис [cron-job.org](https://cron-job.org/en/). Ставь интервал **10 минут**, чтобы оставить запас до порога сна; ровно 15 минут может оказаться слишком поздно.

1. Создай аккаунт на cron-job.org и новое задание.
2. Укажи параметры из таблицы.
3. Запусти ручную проверку задания и убедись, что ответ имеет статус HTTP 200.
4. Сохрани и включи задание.

| Параметр | Значение |
| --- | --- |
| Название | `Tilda MCP Keep Alive` |
| URL | `https://tilda-mcp-render-gateway.onrender.com/healthz` |
| Метод | GET |
| Расписание | Каждые 10 минут |
| Cron, если нужен | `*/10 * * * *` |
| Авторизация | Не требуется |

Ожидаемый ответ:

```json
{"ok":true,"service":"tilda-mcp-gateway"}
```

Для пробуждения используй именно `/healthz`: этот обработчик не обращается к Tilda или базе при каждом запросе. Пароли и ключи в планировщик вводить не нужно. HTTP 200 подтверждает работу процесса, но не проверяет действительность токенов и доступность проектов.

По [условиям Render Free](https://render.com/docs/free), **750 бесплатных часов в календарный месяц делятся между всеми бесплатными веб-сервисами рабочего пространства**. Одному сервису при непрерывной работе нужно 720 часов за 30 дней или 744 часа за 31 день. Для одного шлюза этого хватает; другие бесплатные веб-сервисы расходуют тот же лимит. Количество сохранённых ключей и сайтов само по себе не умножает часы работы.

Периодические запросы помогают избежать сна из-за простоя, но не гарантируют непрерывную доступность и не отменяют лимиты Render, перезапуски или деплои. После сна первое пробуждение может занять около минуты.

## Если подключение не работает

| Симптом | Что проверить |
| --- | --- |
| `PUBLIC_BASE_URL must be the HTTPS public origin` | Укажи HTTPS-адрес своего сервиса Render без пути `/mcp/tilda`, query-параметров и завершающего слеша. |
| `Invalid origin` | Дождись деплоя актуального кода, закрой старую форму и начни подключение из ChatGPT заново. В текущем коде используется `Referrer-Policy: same-origin`; проверка Origin остаётся строгой. |
| `Incorrect owner password` или старое `Incorrect password or session` | Нужен текущий `ADMIN_PASSWORD` из Render, а не токен Tilda. Если форма устарела, открой новую из ChatGPT. |
| `Login session cookie is missing or was replaced` | Эта ошибка относится к старой реализации OAuth. Проверь свежий деплой и начни вход заново: актуальная OAuth-форма от cookie не зависит. |
| Кнопка подключения ничего не делает, в консоли `form-action 'self'` | Обнови код до 0.4.1 или новее и заново открой форму. Исправление разрешает в CSP только проверенный callback текущего OAuth-запроса. Уже открытая страница сохраняет прежнюю CSP. |
| Форма просрочена или её подпись недействительна | Начни новое подключение из ChatGPT; форма действует 10 минут. Не используй старый адрес авторизации из истории. |
| Не появились `list_connections` и другие инструменты реестра | Переподключи приложение после обновления с 0.3 и обнови список инструментов в ChatGPT. |
| Tilda возвращает 401/403 | Проверь права и срок действия исходного ключа. Замени его на странице `/settings`. |
| Хранилище недоступно | Проверь `DATABASE_URL`, права роли Neon и журнал запуска Render. |
| Первый запрос долго выполняется | Открой `/healthz`, дождись HTTP 200 и повтори запрос. Проверь внешнее расписание пробуждения. |

Не отключай CSP и проверку Origin для обхода ошибки. Не меняй `OAUTH_SIGNING_SECRET` при переавторизации: это сделает сохранённые ключи нечитаемыми.

## Обновление с 0.3

1. Добавь DATABASE_URL в Render и передеплой.
2. Открой /settings и добавь именованные ключи.
3. Переподключи MCP-приложение в ChatGPT один раз, чтобы получить доступ к списку подключений, и обнови инструменты.

Старые OAuth-доступы с одним зашифрованным ключом продолжают работать в прежнем режиме и не становятся автоматически доступами ко всем сохранённым ключам. Они не мигрируются в базу скрыто. Чтобы отозвать старый доступ немедленно, отзови соответствующий исходный токен в Tilda.

Если DATABASE_URL ещё не задан, режим одного токена остаётся доступен, а /settings сообщает об отсутствии постоянного хранилища. Ничего не сохраняется в RAM под видом постоянного хранилища.

## Безопасность и ограничения

- Пароль, HTTPS Origin, CSRF, Secure/HttpOnly cookies защищают страницу управления. OAuth-форма не зависит от cookie: сервер требует точное совпадение Origin, действительную подпись формы со сроком 10 минут и привязкой к client/callback/PKCE/resource, а также пароль владельца. Форма использует Referrer-Policy: same-origin, чтобы браузер не заменял Origin на null. Чужой, отсутствующий и null Origin отклоняются.
- Ключи в базе зашифрованы AES-256-GCM с привязкой к ID записи. Отдельный ключ производится через HKDF. OAuth-токены режима нескольких подключений содержат право доступа к реестру, но не ключи Tilda.
- Все вызовы идут только на `https://tilda.kz/api/mcp/`. Клиент не может задать произвольный upstream.
- На каждый вызов создаётся отдельная MCP-сессия Tilda с выбранным ключом. Ответы SSE обрабатываются по мере поступления. Автоматических повторов операций записи нет.
- Форма проверяет формат ключа. Действительность и права проверяются при вызове Tilda.
- Персональные OAuth access-токены живут час, refresh-токены 30 дней. Нет индивидуального server-side отзыва OAuth-грантов и обнаружения повторного refresh. Защита от повторного обмена authorization code хранится в памяти до перезапуска; для строгой одноразовости между рестартами потребуется отдельный постоянный реестр OAuth-кодов.
- Render Free засыпает после 15 минут простоя. Перед подключением можно открыть /healthz и дождаться пробуждения. Возможны таймауты первого запроса.
- Не включай логирование тел запросов, Authorization или DATABASE_URL. Не публикуй секреты.
- Бэкапы Neon и хранение ключа шифрования остаются ответственностью владельца.

## Локальная разработка и проверка

Node 24. `npm ci`, затем `npm test`.

Тесты запускают настоящие HTTP-обработчики OAuth и настроек, проверяют шифрование, CSRF, Origin, ключи с названиями, переименование/замену/удаление и выбор проекта. SQL Neon исполняется на локальном PostgreSQL-движке PGlite; это не проверка доступности конкретного облачного проекта Neon. Внешняя Tilda заменена тестовыми ответами.

Альтернативное локальное хранилище SQLite: задай абсолютный DATA_DIR. На Render оно разрешается только при явном PERSISTENT_DISK_CONFIRMED=yes и реально подключённом постоянном диске. На Render Free вместо этого используется Neon.

Для этого развёртывания живой маршрут уже проверен, см. статус выше. При установке своей копии проверь его заново: подключись из веб-чата ChatGPT, получи список сохранённых подключений и запроси проекты или страницы с реальным ключом. Локальные тесты и ручные HTTP-запросы не заменяют эту проверку.

### Проверка настоящим Chromium

`npm run test:browser` запускает отдельную браузерную проверку двух callback URL ChatGPT. Для установленного Chromium задай BROWSER_EXECUTABLE_PATH; иначе установи Chromium для playwright-core. Браузер обращается к перехваченным тестовым HTTPS-адресам, а не к настоящему аккаунту ChatGPT. Проверяются пустые необязательные поля, отправка формы, редирект, PKCE-обмен кода и tools/list. Реальные пароли, ключи Tilda и Neon не используются.

OAuth-страница разрешает в CSP form-action свой origin и только проверенный callback текущего запроса. Иначе Chromium может блокировать редирект после успешного POST. Настройки /settings по-прежнему разрешают отправку форм только на свой origin.
