# Tilda MCP gateway · именованные подключения

Один универсальный MCP для веб-чата ChatGPT. Именованные ключи хранятся в Neon в зашифрованном виде. Управлять ими можно на защищённой странице сервера. В каждом запросе явно выбирается подключение; параллельные чаты не переключают общий активный проект.

- MCP: `https://tilda-mcp-render-gateway.onrender.com/mcp/tilda`
- Управление: `https://tilda-mcp-render-gateway.onrender.com/settings`

Работает независимо от Codex и компьютера владельца. Это персональный шлюз одного владельца, не многопользовательский сервис.

## 1. Neon

Создай отдельный проект Neon на Free: https://console.neon.tech/.
В проекте нажми Connect, выбери базу и роль и скопируй PostgreSQL connection string.
Вставь **только в Render Environment** под именем DATABASE_URL. Не отправляй строку в чат и не сохраняй в GitHub: она содержит пароль базы.

Приложение при первом запуске создаёт только свою схему `tilda_gateway` и таблицу `connections`. Имена и значения передаются параметрами. Схема и таблица закрыты для PUBLIC. Используй отдельную базу для шлюза; не включай публичный Data API для этой схемы.

## 2. Render

New → Web Service → репозиторий DiasMazhenov/tilda-mcp-render-gateway → ветка main.

| Настройка | Значение |
| --- | --- |
| Runtime | Node |
| Build | `npm ci --omit=dev` |
| Start | `npm start` |
| Health Check | `/healthz` |
| Plan | Free для начала |

Environment:

| Переменная | Значение |
| --- | --- |
| NODE_VERSION | `24` |
| PUBLIC_BASE_URL | `https://tilda-mcp-render-gateway.onrender.com`, без пути и завершающего слеша |
| OAUTH_SIGNING_SECRET | 64 случайных hex-символа, например результат `openssl rand -hex 32` |
| ADMIN_PASSWORD | Уникальный пароль от 10 символов |
| DATABASE_URL | Строка подключения Neon из Connect |

Все ключи Tilda вводятся через интерфейс. Переменных TILDA_TOKEN_* нет.

Не меняй OAUTH_SIGNING_SECRET после сохранения ключей: от него производится ключ шифрования базы. Если его потерять, сохранённые ключи Tilda нельзя будет расшифровать. Для переноса сохрани зашифрованную базу и этот секрет отдельно в менеджере паролей. Пароль владельца можно менять; это завершает старые сессии страницы настроек, но не отзывает уже выданные OAuth-доступы ChatGPT.

После сохранения настроек дождись Live. `/healthz` проверяет работу процесса, а не действительность ключей Tilda.

## 3. Добавление нескольких ключей

1. Открой `/settings`.
2. Войди с ADMIN_PASSWORD.
3. Введи название проекта и токен Tilda MCP. Префикс Bearer необязателен.
4. Добавь остальные проекты.

Ключи после сохранения не выводятся ни в HTML, ни в список MCP-подключений. Можно менять названия, заменять токены и удалять записи. Пустое поле нового токена при редактировании сохраняет прежний. Одинаковые названия без учёта регистра не допускаются. Удаление требует отдельной галочки.

После удаления подключения новые вызовы по его ID прекращаются. Уже выполняющийся запрос не отменяется.
Название подключения не ограничивает исходный токен одним проектом Tilda: реальные права определяет Tilda.

## 4. Подключение веб-чата

Создай пользовательское MCP-подключение в ChatGPT:

| Поле | Значение |
| --- | --- |
| Название | Tilda MCP |
| Server URL | `https://tilda-mcp-render-gateway.onrender.com/mcp/tilda` |
| Authentication | OAuth |
| Client registration | DCR |
| Client ID / Secret | Не заполняются вручную |
| Token endpoint auth method | none |

CIMD не требуется. При авторизации введи пароль владельца. Новый именованный ключ можно добавить в этой форме или позже на странице /settings. При настроенной базе поля нового ключа необязательны: достаточно уже сохранённых подключений.

Стандартные настройки ChatGPT не расширяются произвольными полями. Управление ключами находится на защищённой странице шлюза; ссылку также возвращает list_connections.

### В переписке

Примеры:
- Покажи сохранённые подключения Tilda.
- Покажи доступные инструменты проекта «Название проекта».
- Для проекта «Название проекта» покажи страницы.

Инструменты шлюза:
- `list_connections`: названия и ID без секретов, ссылка управления.
- `list_tilda_tools(connection_id)`: реальные имена, описания и схемы инструментов Tilda для выбранного ключа.
- `call_tilda_tool(connection_id, tool_name, arguments)`: вызов выбранного инструмента.

Активного проекта на весь сервер нет. Каждый вызов обязан содержать connection_id. Если название не указано или непонятно, агент должен уточнить выбор. Переименование сохраняет ID. Замена токена действует для следующих вызовов без переподключения плагина.

Обёртка call_tilda_tool помечена как потенциально изменяющая данные, поскольку через неё доступны и чтение, и запись. Подтверждения зависят от настроек ChatGPT. Секреты нельзя добавлять через чат: только через защищённую форму.

## Обновление с 0.3

1. Добавь DATABASE_URL в Render и передеплой.
2. Открой /settings и добавь именованные ключи.
3. Переподключи MCP-приложение в ChatGPT один раз, чтобы получить доступ к списку подключений, и обнови инструменты.

Старые OAuth-доступы с одним зашифрованным ключом продолжают работать в прежнем режиме и не становятся автоматически доступами ко всем сохранённым ключам. Они не мигрируются в базу скрыто. Чтобы отозвать старый доступ немедленно, отзови соответствующий исходный токен в Tilda.

Если DATABASE_URL ещё не задан, режим одного токена остаётся доступен, а /settings сообщает об отсутствии постоянного хранилища. Ничего не сохраняется в RAM под видом постоянного хранилища.

## Безопасность и ограничения

- Пароль, HTTPS Origin, CSRF, Secure/HttpOnly cookies защищают страницу управления. Форма входа использует Referrer-Policy: same-origin, чтобы браузер не заменял Origin на null.
- Ключи в базе зашифрованы AES-256-GCM с привязкой к ID записи. Отдельный ключ производится через HKDF. OAuth-токены режима нескольких подключений содержат право доступа к реестру, но не ключи Tilda.
- Все вызовы идут только на `https://tilda.kz/api/mcp/`. Клиент не может задать произвольный upstream.
- На каждый вызов создаётся отдельная MCP-сессия Tilda с выбранным ключом. Ответы SSE обрабатываются по мере поступления. Автоматических повторов операций записи нет.
- Форма проверяет формат ключа. Действительность и права проверяются при вызове Tilda.
- Персональные OAuth access-токены живут час, refresh-токены 30 дней. Нет индивидуального server-side отзыва OAuth-грантов и обнаружения повторного refresh. Защита от повторного обмена authorization code хранится в памяти до перезапуска; для строгой одноразовости между рестартами потребуется отдельный постоянный реестр OAuth-кодов.
- Render Free засыпает после 15 минут простоя. Перед подключением можно открыть /healthz и дождаться пробуждения. Возможны таймауты первого запроса.
- Не включай логирование тел запросов, Authorization или DATABASE_URL. Не публикуй секреты.
- Бэкапы Neon и хранение ключа шифрования остаются ответственностью владельца.

## Локальная разработка и проверка

Node 24. `npm ci`, затем `npm test`.

Тесты запускают настоящие HTTP-обработчики OAuth и настроек, проверяют шифрование, CSRF, Origin, ключи с названиями, переименование/замену/удаление и выбор проекта. SQL Neon исполняется на локальном PostgreSQL-движке PGlite; это не проверка доступности конкретного облачного проекта Neon. Внешняя Tilda заменена тестовыми ответами.

Альтернативное локальное хранилище SQLite: задай абсолютный DATA_DIR. На Render оно разрешается только при явном PERSISTENT_DISK_CONFIRMED=yes и реально подключённом постоянном диске. На Render Free вместо этого используется Neon.

Живой маршрут ChatGPT → Render → Neon → Tilda нужно проверить после ввода реальных настроек. Браузерный вход необходимо повторить из ChatGPT; ручные HTTP-тесты не заменяют проверку OAuth в интерфейсе.
